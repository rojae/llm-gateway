# 기업 SSO·모니터링 검증 기록

검증일: 2026-09-26. 로컬의 격리된 PostgreSQL 17, Redis 7.2, Keycloak 26.4.7과 합성 데이터로 검증했습니다. 회사 운영 계정, 실제 공급자 추론, 외부 클러스터는 사용하지 않았습니다.

## 자동화 검증

- `./scripts/test-analytics.sh`: Java 테스트 **198개**, 실패·오류·건너뜀 **0개**. 일회용 PostgreSQL과 Redis를 생성하고 종료 시 정리합니다.
- Python 스크립트 테스트 **17개 통과**.
- 당시 Spring Boot 실행 JAR 빌드, 화면 JavaScript 구문 검사, 테스트 실행기 셸 구문 검사 통과. 현재 멀티 모듈 구조의 빌드 명령은 `./gradlew :llm-gateway-api:bootJar`입니다.
- 서명 JWT의 issuer·audience·만료·조직·역할 검증, PKCE·CSRF·로그아웃, 기존 Anthropic/OpenAI 프록시 회귀를 포함합니다.
- 조직 간 동일 요청 ID의 격리, viewer 본문 제한, 감사 기록 실패 시 본문 반환 차단, 수집 키 만료·폐기·조직 위조·저장 중 재검증을 확인했습니다.
- 보관기간 삭제와 본문 저장이 겹치는 동시성 테스트는 이전 단일 SQL 구현에서 실패하고 수정 구현에서 통과했습니다. 삭제된 요청의 본문이 남거나 재적재로 되살아나는 경우를 방지합니다.

## 실제 실행 검증

| 항목 | 확인한 결과 |
| --- | --- |
| Keycloak 로그인 | 브라우저 Authorization Code + PKCE S256, state·nonce, 등록 콜백 사용 |
| 복제본 세션 | 같은 Redis를 사용하는 두 Java 프로세스를 번갈아 호출해 동일한 조직·역할로 200 응답 |
| 권한 | viewer 상세의 본문은 비어 있음, 수집 키·감사 API는 403, 다른 조직 전용 요청은 404 |
| 수집 키 | 발급 시에만 평문 표시, 닫은 후 화면에서 제거, 폐기 후 전송 거부, 감사 이벤트 기록 |
| 구독 텔레메트리 | 같은 이벤트 재전송은 한 건만 저장, 위조 조직 값 무시, 임의 프롬프트 필드 저장 안 함 |
| 비용 표시 | API 비용과 구독 사용량의 API 환산액을 별도 표시 |
| 본문 화면 | 요청·응답 분리, 다른 조직 본문 미노출, HTML/스크립트를 실행하지 않고 텍스트로 표시 |
| 로그아웃·CSRF | 로그아웃 204, 이전 세션 재사용 401, CSRF 없는 변경 요청 403 |
| 장애 복구 | 기존 구성에서 PostgreSQL·Redis 각각의 중단과 앱 재시작 없는 복구를 확인했습니다. 이름 변경 후 새 구성에서도 로컬 모드 PostgreSQL 장애 및 복구를 주입해 readiness 200/200, dependencies 503/200, `/healthz` 200을 확인했습니다. 새 구성의 엔터프라이즈 Redis 장애 주입은 아직 재검증하지 않았습니다. |
| 어드민 화면 | 데스크톱 1440px·모바일 390px 확인, 수집 키 27개 페이지 전환, 모바일 감사 표 가로 스크롤 확인 |
| 백업 복원 | `pg_dump`를 새 DB에 복원해 V1–V5와 8개 테이블 건수 일치, 감사 기록 수정 금지 유지 |
| 컨테이너 | non-root·읽기 전용 루트 파일시스템에서 기동, 별도 관리 포트 상태 검사, 선택적 본문 파일을 쓰기 가능한 볼륨에 생성 |
| 배포 구성 | `kubectl kustomize deploy/enterprise` 렌더링 성공 |

브라우저 시험은 명시적인 loopback HTTP 테스트 설정을 사용했습니다. 운영 HTTPS 설정에서는 Secure 쿠키를 사용하지만 고객 TLS 종료 장비를 통한 실측은 위 결과에 포함되지 않습니다.

위 화면 검증은 구조 변경 이전 기록입니다. 분리된 `llm-gateway-admin` Next.js/React 화면과 `/admin` 진입, API rewrite, `GW_ADMIN_UI_URL`을 통한 SSO 이동은 새 구성에서 다시 검증해야 합니다. Spring Boot API 컨테이너는 `llm-gateway-api`만 빌드하므로 화면은 별도 Next.js 서비스로 배포해야 합니다.

## 운영 적용 전 남은 검증

실제 Entra ID·Okta 고객 계정, 회사별 MFA·클레임 정책, 운영 DNS/TLS, Kubernetes 네트워크 정책 시행, 가용 영역 장애, 부하 시험과 RPO/RTO는 검증하지 않았습니다. 이 기록은 해당 환경의 운영 인증을 대신하지 않습니다.

설정은 [SSO 연결](sso.md), 배포·보관기간·복원 절차는 [운영 가이드](operations.md), 구독 사용량 전송은 [어드민 가이드](admin.md#구독-claude-code-모니터링)를 따릅니다.
